\title{Do LLMs Silently Compute the Wrong Thing?\\
Measuring Silent Semantic Errors in LLM Data-Transform Code\\
and Detecting Them with Specification-Derived Operator Contracts}
\author{Anonymous Submission}
\affiliations{Paper under double-blind review}

\begin{document}
\maketitle

\begin{abstract}
Large language models increasingly write the \emph{data-transform} code behind
analyses and figures---group-wise medians, weighted means, joins, pooled rates.
We show that a large fraction of this code is \emph{silently} wrong: it runs
without error and produces plausibly-shaped output, yet computes a different
quantity than the user asked for. The hazard is \emph{executable and gold-free}:
an under-specified request admits several defensible readings that \emph{disagree
materially} on the actual table, and the model \emph{silently commits} to one
without flagging the fork. On real Nature source-data tables, frontier models
commit away from the natural reading in \textbf{77\%} of \emph{ambiguously}-phrased
data-transform tasks (10\% when disambiguated), and the
failure is \emph{invisible} to every simple safeguard: deterministic checks
(execution, shape, range, self-consistency) catch \textbf{0\%}, and LLM
self-critique misses 39\% while false-flagging 40\%---a pervasive, invisible
failure mode whose measurement is our primary contribution. As a goldless remedy
where the operator is known or inferable, we introduce
\emph{specification-derived operator contracts}: executable checks over the
(input, parameters, result) triple that certify an operator's semantics using
\emph{no per-task gold answer}---the specification comes from the operator
intent, not a stored label, and can be auto-synthesized from a natural-language
goal. Across two real-data slices (up to 1{,}855 checks) they flag silent
errors at \textbf{98--99\% recall / 0.2\% false-positive} under a \emph{known}
operator, where existing checks are structurally blind---about
a third via \emph{pure relational invariants} that compute no
reference value (a \emph{five-family} non-circular core; 99.8\% on the large real slice)
and the rest via \emph{parameterized recomputation}
that presupposes the operator (96.6\%). We show the contracts can be
synthesized from a high-level goal (78--83\% correct, $N{=}23$, one-shot),
transfer across execution substrates unchanged (pandas${\to}$SQL, 10/10
operators), and drive a zero-training repair recipe (75\% vs.\ 12\% for strong
self-debug). Finally, we run the \emph{entire} pipeline---infer operator, ground
column roles, synthesize contract, detect---from only a messy request and a raw
table, catching 51--58\% of silent errors with nothing structured provided---a
useful early-warning floor, far below the known-operator regime rather than a
deployable replacement for it. We
frame the work \emph{measurement-first}---a common, invisible failure quantified,
with operator intent (once recovered) making it checkable without a per-task gold
answer---a \emph{goldless executable verifier} for the verifiable-reward and
data-agent regime where no per-task reference exists---and release the
measurement suite and code.
\end{abstract}

\section{Introduction}
% =============================================================================
Code-writing assistants now sit in the middle of everyday data analysis: a user
describes what they want in plain language (``give me the typical expression per
cell type''), and the model returns \texttt{pandas} (or SQL) that computes it.
When that code has a \emph{syntactic} bug it crashes; when it has an obvious
numeric bug the plot looks wrong. The dangerous case is the third one: the code
\emph{runs}, the output has the right shape and a believable range, and it is
nonetheless the answer to a \emph{different question}---a mean where the user
meant a median, a per-row ratio averaged instead of a pooled rate, an inner join
that silently drops unmatched rows. We call these \textbf{silent semantic
errors}.

Silent semantic errors are pernicious precisely because the standard safety net
does not see them. Execution-based evaluation (``does it run?''), shape/type
validity, and self-consistency across samples all pass, because the wrong code
is still \emph{valid} code producing \emph{valid-looking} output. Verifying the
\emph{meaning} of the result normally requires a per-task gold reference---but in
deployment there is none: if we already knew the right answer we would not be
asking the model.

\paragraph{This paper.} We make three moves. \textbf{(1) Measurement}---our
primary contribution. We
quantify how often frontier LLMs silently compute the wrong data transform, on
\emph{real} scientific data (Nature source-data tables) and across models, and
quantify how completely existing checks miss it. \textbf{(2) A
specification-derived detector} for the known- or inferred-operator regime. We introduce \emph{typed operator contracts}:
executable checks of an operator's semantics---conservation laws, per-group
identities, row-count and range constraints, or, where appropriate, an
intent-derived recomputation---evaluated over the (input, params, result) triple
with \emph{no per-task gold label}. \textbf{(3) From assertions to an AI
pipeline.} The contracts are not a hand-written wall of \texttt{assert}s but the
core of a system that \emph{grounds an informal request into a verifiable
specification}: it infers the operator and column roles from a messy request,
synthesizes the invariant from a natural-language goal, and repairs the
code---end to end.

\paragraph{Where this sits.} The target is the reliability of \emph{LLM
data-analysis agents}---the systems now writing the \texttt{pandas}/SQL behind
scientific figures and reports---and the work connects three current threads:
ambiguity-aware code generation \citep{clarifycodebench,orchid}, verifiers and
verifiable rewards, and reference-free (goldless) verification. Our angle is a
goldless, executable, and \emph{reward-hack-resistant} check for
\emph{consequential intent ambiguity} in real data analysis---a signal that can
gate, flag, or (at inference time) reward.

\paragraph{What ``no gold'' means.} A contract needs \emph{no per-task
human-labeled answer}---it derives from the operator's \emph{specification}. For
some operators it is a \emph{pure invariant} no implementation pins down
(within-group shares sum to one \emph{per group}; a left join keeps every left
row); for others it \emph{recomputes} the expected value from the known operator
and checks agreement. The assumption is not ``no reference is ever computed'' but
that the \emph{operator and roles are known or inferred}---we measure separately
what happens when they must be recovered (Sec.~\ref{sec:e2e}).

\paragraph{Contributions.}
\begin{enumerate}
\item \textbf{A measurement study} of silent semantic errors in LLM
data-transform code: 77\% under author-designed ambiguous requests (10\% disambiguated),
32--65\% across eight models and four vendors, 26\% on external DS-1000;
deterministic
checks detect 0\%, self-critique 61\% recall at 40\% false-positive
(Sec.~\ref{sec:measure}).
\item \textbf{Specification-derived operator contracts} that, \emph{given a
known or inferred operator}, flag the errors at 98--99\% recall / 0.2\%
false-positive on real tables---anchored by a \emph{five-family} pure-invariant
core that derives no reference value (99.8\% on the large real slice),
the rest presupposing the operator---where
code-layer baselines are structurally blind (Sec.~\ref{sec:detect}).
\item \textbf{Grounding intent into a specification}: the invariant can be
auto-synthesized from a high-level goal (78--83\%, $N{=}23$, one-shot; stable
across GPT and Gemini), and the operator (98\%) and column roles (74--83\%) can
be recovered from a keyword-free request (Sec.~\ref{sec:synth}--\ref{sec:e2e}).
\item \textbf{An end-to-end pipeline} run on \emph{real} Nature tables from only
a messy request and a raw table---nothing structured given---catching 51--58\%
of silent errors, plus \textbf{substrate-agnostic transfer}
(pandas${\to}$SQL, 10/10 operators, zero SQL-specific code) and a
\textbf{zero-training repair recipe} (targeted 75\% vs.\ 12\% strong self-debug;
Sec.~\ref{sec:e2e}--\ref{sec:repair}).
\item \textbf{Honest, quantified boundaries}: the method's power lives where
operator-level intent is recoverable; on raw free-text code operator inference
is the bottleneck, and a calibrated scope-gate makes out-of-scope inputs
\emph{safely abstain} (Sec.~\ref{sec:limits}).
\end{enumerate}

\section{Related Work}\label{sec:related}
% =============================================================================
\paragraph{Evaluating LLM code generation.} HumanEval, MBPP, and DS-1000
\citep{chen2021humaneval,austin2021mbpp,lai2023ds1000} score functional
correctness against \emph{hidden tests or a gold reference}; execution-based
agent evaluation (e.g., SWE-bench \citep{jimenez2024swebench}) assumes a
checkable oracle. Our setting is complementary and harder: no per-task reference
exists at inference time, and the code already passes execution.

\paragraph{Data validation and pipeline testing.} Practitioner frameworks such
as Great Expectations, \texttt{pandera}, and dbt tests
\citep{gx2020,pandera2020} let engineers assert schemas, ranges, and
distributional expectations on tables. These are \emph{hand-authored per
dataset} and check \emph{surface} properties (types, nullability, bounds)---
exactly the properties that silent semantic errors preserve. We instead check
\emph{operator semantics} and \emph{synthesize} the check from intent.

\paragraph{Property-based and metamorphic testing.} Property-based testing
\citep{claessen2000quickcheck} and design-by-contract \citep{meyer1992dbc} predate
us by decades; metamorphic testing \citep{chen1998metamorphic} verifies relations
between outputs without a gold oracle. Invariant mining (Daikon;
\citealp{ernst2007daikon}) automatically discovers likely assertions from a corpus
of \emph{correct} executions; we instead derive the assertion from
natural-language \emph{intent}, with no correct execution to mine. Our mechanism
is in this family. Our
contribution is not the mechanism of asserting a property but (i) an
\emph{empirically-grounded} taxonomy of the operator-level slips LLMs actually
make, (ii) checks that need \emph{no per-task gold and can be
\underline{synthesized from natural language}}, and (iii) a pipeline that
\emph{grounds a free-text request into the right invariant}---turning
property-based testing from a developer tool into an inference-time detector.
Concretely, a generic PBT or metamorphic tool cannot flag a global-vs-per-group
share slip on its own: \emph{which} property to enforce (shares sum to one per
group, not globally) \emph{is} the user's inferred intent. Selecting and
instantiating that invariant from a messy request is the inference problem we
solve; the assertion itself is deliberately old and simple.

\paragraph{Validating LLM outputs without gold.} Self-consistency
\citep{wang2023selfconsistency}, self-critique / self-refine
\citep{madaan2023selfrefine}, LLM-as-judge \citep{zheng2023judge}, and
execution-guided verification (e.g., LEVER \citealp{ni2023lever}) estimate
correctness without a reference. We show these miss silent semantic errors
(self-critique: 61\% recall at 40\% false-positive); our consensus $+$
metamorphic refinement is a goldless \emph{verification signal} in the spirit of
metamorphic testing.

\paragraph{Verifiers and verifiable rewards.} Outcome verifiers
\citep{cobbe2021gsm8k}, process reward models \citep{lightman2023verify}, and RL
from \emph{verifiable} rewards \citep{deepseekr1} drive much of the recent gain in
reasoning and code, and test-time verification turns extra inference compute into
accuracy \citep{snell2024testtime}. Each assumes a checkable signal exists---unit
tests, an answer key, or a learned reward. Because our contract is a \emph{sound}
executable invariant rather than a learned reward, it is far harder to
\emph{reward-hack} than model-based verifiers. We find it pays off at \emph{test
time} (goldless selection and repair feedback, Sec.~\ref{sec:repair}) but, used
as an offline preference label, does not improve an open model---optimizing a
goldless (necessary-but-not-sufficient) signal Goodharts---a concrete data point
on where goldless verifiers help and where they invite reward-hacking.

\paragraph{LLMs for data science and visualization.} Chart/plot benchmarks and
code-/visual-similarity judges (MatPlotAgent, Plot2Code, ChartMimic, VisEval)
\citep{yang2024matplotbench,wu2024plot2code,shi2024chartmimic,chen2024viseval}
score whether a figure \emph{looks} right, not whether the plotted numbers
\emph{equal} the data. We measure and detect the upstream data-transform error
such judges cannot see. Table~\ref{tab:position} summarizes these distinctions.

\section{Problem Formulation}\label{sec:problem}
% =============================================================================
A \emph{data-transform task} is a triple $(D, \iota, \theta)$: an input table (or
tables) $D$, a natural-language intent $\iota$, and column-role parameters
$\theta$ (which column is the group, the value, the weight, \dots). Real intents
are routinely \emph{under-specified}: ``a typical value per group'' admits a set
of defensible operator readings $\mathcal{G}=\{g_1,\dots,g_k\}$ (mean vs.\ median;
per-group vs.\ global share; pooled rate vs.\ mean-of-ratios; inner vs.\ left
join). The task is \textbf{consequentially ambiguous} on $D$ when these readings
\emph{disagree materially}---$\exists\,g_i,g_j\in\mathcal{G}:\
\lVert g_i(D){-}g_j(D)\rVert>\tau$---an \emph{executable, gold-free} property
(run the readings and compare; on our operator fixtures all forks exceed
$\tau{=}1\%$, often by orders of magnitude). A model emits code $f$ with $r=f(D)$;
the failure we target is a \textbf{silent commitment}: $f$ executes, $r$ is
schema-valid, and the model commits to one reading \emph{without surfacing the
fork}. Whether the commitment is ``wrong'' need not appeal to a stored answer---the
readings' disagreement already establishes the hazard. As a \emph{directional}
refinement we take the natural-phrasing reading $g\in\mathcal{G}$ as a reference
and call $r$ a \textbf{silent semantic error} when it commits away from it
($r\neq g(D)$); $g$ is a reference for that directional rate, \emph{not} a claim
that it is the uniquely correct answer.

A \textbf{specification-derived contract} for an operator $o$ is a function
$C_o(D,\theta,r)\in\{\textsf{fire},\textsf{pass}\}$ that identifies \emph{which
reading} $r$ computed and fires when it is a confusable alternative to $o$'s
intended semantics. $C_o$ uses \emph{no per-task gold label}: it is a function of
the operator specification alone (instantiated at the given $\theta$). We evaluate
it on held-out correct and slip implementations by two properties: it \emph{fires
on the silent slip} (recall) and \emph{passes on every valid implementation},
including order/representation-diverse correct ones (false-positive robustness).
Crucially $C_o$ reads only $(D,\theta,r)$---never the code $f$---so it is
agnostic to how $r$ was produced (Sec.~\ref{sec:sql}). The strong assumption is
that the operator $o$ and roles $\theta$ (the reading menu) are known or
inferable; Sec.~\ref{sec:e2e} removes it by inferring them from $\iota$.

\section{Measurement: How Common, How Invisible}\label{sec:measure}
% =============================================================================
\paragraph{Corpus and protocol.} We pair Nature figures with their Source-Data
tables and instantiate operator-semantic tasks (median-vs-mean, within-group
share, weighted mean, pooled rate, NaN-as-zero, \dots) on the real tables, so
the tables and their columns are real scientific data, \emph{not} authored by
us; the operator set (24 operators grounded in observed real-data slips, not
chosen post hoc; released), its gold transform, and the ambiguous/clarified prompts
are fixed author-written templates instantiated on those tables (table-level
independence, not task-level). Each task carries a matched pair of prompts: an \emph{ambiguous} phrasing
(``a typical value per group''---the natural way a hurried analyst asks) and a
\emph{clarified} phrasing that names the disambiguation. Gold is the template
transform; a response is scored \emph{silent} if it runs, is schema-valid, and
disagrees with gold. We report over a 71-article independent sample (each
article contributes a capped number of tasks) with 95\% Wilson intervals.

\paragraph{Prevalence.} Under the ambiguous phrasing, frontier models emit a
silent semantic error on \textbf{77\%} of real Nature tasks
($1296/1682$, CI $75$--$79$); disambiguating the request drops this to
\textbf{10\%} ($175/1682$, CI $9$--$12$; $21\%$ on a larger 229-article slice). The gap is the point: much of the
danger is \emph{under-specification} that the model resolves the wrong way, and
the rate is \textbf{40--60\%} across five frontier models and three vendors on
the expansion grid (Table~\ref{tab:crossmodel}; \textbf{32--42\%} for the same
models on the core grid), rises to \textbf{65\%} for smaller open models
(Qwen-2.5-Coder-7B, falling to 44\% at 32B), and is \textbf{26\%}
on external DS-1000, so it is a property of the task family, not one model
(Fig.~\ref{fig:prev}).

\paragraph{Invisibility.} We measure what existing safeguards catch on the
operator grid (Table~\ref{tab:baselines}). Deterministic checks---execution, shape/type,
value-range, multi-sample consistency---catch \textbf{0\%}: the wrong code runs,
is shaped correctly, and is \emph{stably} wrong. Multi-sample consistency stays at
$0\%$ even when the $K$ samples are drawn at temperature $0.8$ (recall $0/38$):
the silent errors are \emph{common-mode}---the model resamples the same wrong
transform ($92\%$ of tasks give identical output even at $T{=}0.8$), so
disagreement-based checks never fire. LLM self-critique---the same model, shown
the \emph{clarified} request and a preview of the produced table and asked in one
turn for a JSON correct/incorrect verdict---catches 61\%
but false-flags 40\%, unusable as a gate; note this is a \emph{favorable} setup
(the judge is handed the disambiguated intent, not the ambiguous one) and it
still fails. Re-running the same five detectors
\emph{directly} on the real Nature slice (119 tasks) confirms this is not an
artifact of the synthetic grid: execution, validity, and multi-sample consistency
stay at $0\%$ recall on real data, and self-critique is if anything worse in the
wild (62\% recall at 67\% false-positive), while our contracts hold at
$100\%$/$0\%$.

\section{Specification Contracts as an AI Pipeline}\label{sec:method}
% =============================================================================
\subsection{Typed operator contracts}
Each operator is certified by one small check ($\approx$10 lines, reading only
$(D,\theta,r)$). Examples: a \emph{weighted mean} must equal $\sum v_iw_i/\sum
w_i$; \emph{within-group shares} must sum to one
\emph{per group} (not globally); a \emph{pooled rate} equals $\sum\text{num}/
\sum\text{den}$, not the mean of per-row ratios; a \emph{left join} preserves
every left row. Contracts range from pure invariants (share, join) to
intent-derived recomputations (weighted mean); none uses a per-task human label.
The taxonomy of operators is \emph{empirically grounded}---derived from the slip
patterns the measurement study documents---not an arbitrary catalog, and (below)
it is auto-extensible.

\subsection{Synthesizing the specification from language}\label{sec:m-synth}
To show the taxonomy is not a closed hand-written set, we ask a frontier model to
\emph{synthesize} the contract from only the NL goal, the parameter names, and
the result schema---never the reference implementation. To rule out the model
merely \emph{transcribing a stated formula}, we run a \emph{de-leaked} condition
whose intent gives only a high-level goal---no formula and no ``not-the-$X$''
slip-contrast (a plain-language goal may still \emph{imply} the target property
for some operators, a residual we audit in Sec.~\ref{sec:synth}). We score each synthesized contract \textbf{CORE} (fires on the
silent slip \emph{and} passes on the correct implementation) and \textbf{FULL}
(CORE \emph{and} robust to alternative valid implementations).

\subsection{Goldless counterexample-guided refinement}
Synthesis can over-fire on valid alternatives. We add a monotone-safe refinement
loop with a goldless oracle (Fig.~\ref{alg:cegis}): sample $K$ diverse
implementations of the intent, cluster by output into a \emph{consensus}
(probably-correct) set, and treat any contract that fires on a consensus member
as a false-positive counterexample; \emph{metamorphic} perturbations of a
consensus result probe non-triviality. A refinement is accepted only if a
goldless score (consensus-pass $+$ probe-fire) strictly improves, so the loop
never regresses below one-shot by construction. We report this as a
\emph{mechanism with a safety guarantee}, not an accuracy gain
(Sec.~\ref{sec:synth}).

\begin{figure}[t]\centering
\fbox{\begin{minipage}{0.93\columnwidth}\small
\textbf{Goldless refinement of a synthesized contract}\\[2pt]
\textbf{input} intent $\iota$, params $\theta$, input $D$; \textbf{output} contract $C$\\
\rule{\linewidth}{0.3pt}\\
1\ \ $C \leftarrow \textsc{Synthesize}(\iota,\theta)$\hfill\emph{// one-shot}\\
2\ \ $\{f_k\} \leftarrow \textsc{DiverseImpls}(\iota,\theta,K)$\\
3\ \ $S \leftarrow$ largest output-agreement cluster of $\{f_k(D)\}$\hfill\emph{// consensus}\\
4\ \ $P \leftarrow \textsc{Perturb}(s)$ for $s\in S$\hfill\emph{// metamorphic probes}\\
5\ \ \textbf{repeat}\\
6\ \ \ \ \textbf{if} $C$ fires on some $s\in S$ \textbf{then}\hfill\emph{// FP counterexample}\\
7\ \ \ \ \ \ $C' \leftarrow \textsc{Resynthesize}(\iota,\theta,s)$\\
8\ \ \ \ \ \ \textbf{if} $\mathrm{score}(C';S,P) > \mathrm{score}(C;S,P)$ \textbf{then} $C\leftarrow C'$\\
9\ \ \textbf{until} no accepted change\quad\textbf{return} $C$\\[1pt]
\footnotesize$\mathrm{score}(C;S,P)=\#\{s\in S: C\text{ passes}\}+\#\{p\in P: C\text{ fires}\}$; no gold used.
\end{minipage}}
\caption{Monotone-safe goldless refinement. The consensus set $S$ and
metamorphic probes $P$ replace a reference answer; line 8 guarantees the loop
never regresses below the one-shot contract \emph{on the goldless score} (not
necessarily on downstream detection quality).}
\label{alg:cegis}
\end{figure}

\subsection{From a messy request to a check}
Deployed, the system receives only a messy request $\iota$ and a raw table $D$
(Fig.~\ref{fig:pipe}). It (1) infers the operator $\hat o$ from $\iota$,
(2) grounds the column roles $\hat\theta$ from $\iota$ and the column names,
(3) synthesizes $C_{\hat o}$, and (4) checks $r$. When a contract fires, the
same signal drives \emph{repair}: the violated invariant is fed back as a
targeted prompt, and best-of-$N$ selection uses the contract (not gold) to pick
among candidate fixes. Figure~\ref{fig:worked} walks through one real case end to end.

\section{Detection on Real Data}\label{sec:detect}
% =============================================================================
Unless noted, the frontier model is a 2026-era GPT model behind an
OpenAI-compatible API; buggy starting points for repair are \emph{model-generated},
not author-written; intervals are 95\% Wilson.\footnote{Model identifiers
(``GPT-5.4/5.5'', ``Gemini-3.1-Pro'') are the API names available at submission
time; we release prompts, seeds, and all outputs for reproducibility.}

The contracts detect silent errors at \textbf{98\% recall} ($1438/1471$, CI
$97$--$98$) and \textbf{0.2\% false-positive} ($4/1855$, CI $0.1$--$0.6$) on a
71-article independent sample; a second, table-dense slice gives $1398/1408$
recall ($99\%$) and $2/1539$ false-positive. We report the more conservative
71-article number as the headline because it maximizes cross-paper independence.
We stress a distinction the framing depends on: this measures detection under
\emph{known} operator and parameters; the self-authored correctness grid used in
development is a contract \emph{unit test}, not evidence of generalization, and
we exclude it from headline claims. We report the false-positive rate as the
exact fraction $4/1855$ ($0.2\%$) with its interval throughout, rather than
rounding to ``0\%''.

\paragraph{Failure analysis.} The $\sim$2\% of silent errors the contracts miss
are not contract bugs but an inherent \emph{detectability} limit: they
concentrate where the slip's output is numerically near-identical to the correct
one---e.g., a group whose values are near-uniform (so mean $\approx$ median) or a
weight column that is near-constant (so weighted $\approx$ plain mean). There,
\emph{no} invariant can separate the two within tolerance, and the ``error''
has negligible practical effect. The four false-positives arise on degenerate
tables (a single group, or all-equal values) where the invariant is
\emph{undefined} on the correct output (e.g.\ a per-group share of $0/0{=}$NaN),
so the contract fires on a valid result; a schema/degeneracy pre-filter removes them.

\paragraph{Per-operator breakdown.} Detection is uniform across operators, not
driven by one easy case (Table~\ref{tab:perop}): recall is $\geq$99\% for four of
five operators and is only pulled down by \texttt{median-not-mean} (95\%),
exactly the near-tie regime the failure analysis predicts (groups where the
median and mean nearly coincide). Which operator carries the residual misses is
\emph{slice-dependent}---on other real slices \texttt{median-not-mean} is $100\%$
and the misses fall on within-group-share/pooled-rate---so the invariant claim is
that residual misses are near-ties at the chosen tolerance, not that median is
intrinsically the hardest operator.

\paragraph{Two kinds of contract (what ``no gold'' really buys).} We separate
recall by contract class, because the two make different epistemic claims and a
reviewer should see the split rather than a pooled number. A \emph{pure
invariant} certifies a relational property that no single implementation pins
down and derives \emph{no expected value}---within-group shares must sum to one
\emph{per group}, a left join must preserve every left row, a running total's
last entry must equal the column sum. A \emph{recomputation} instead derives the
expected value from the (known or inferred) operator and parameters and checks
agreement---a weighted mean equals $\sum v_iw_i/\sum w_i$, a pooled rate equals
$\sum\text{num}/\sum\text{den}$. We concede the latter amounts to a
\emph{parameterized reference computed on the fly}, not merely an invariant: its
power is real but conditional on knowing the operator. On the real Nature sample
the \emph{pure-invariant} contract (\texttt{within-group-share}) detects at
$538/539=\mathbf{99.8\%}$. Crucially this non-circular core is \emph{not one
operator}: \textbf{five} core contracts derive no reference value---within-group
-share, left-join-keep-all, running-total-equals-column-sum, top-$n$-with-ties,
and count-includes-empty---and on the shared fixtures each fires on its silent
slip while passing the intended transform \emph{and} every
order/representation-diverse valid implementation (recall $5/5$, false-positive
$0$; within-group-share is simply the family member with a large real-data
sample). The \emph{recomputation} contracts
(weighted-mean, pooled-rate, median, nan-as-zero) detect at
$900/932=\mathbf{96.6\%}$. Both need \emph{no per-task human-labeled answer}; the
honest distinction is whether a reference \emph{value} is derived, and we state
plainly that roughly two-thirds of the headline checks are recomputations whose
strength presupposes a known operator (Sec.~\ref{sec:e2e} measures what happens
when it must be inferred).

\subsection{Synthesizing contracts from a goal}

\subsection{Recovering operator and roles from language}
Given a realistic request with \emph{no operator keyword}, the frontier model
recovers the operator on real Nature tasks at \textbf{98\%} ($147/150$, CI
$94$--$99$), while a keyword regex collapses to \textbf{21\%} ($31/150$)---the
model uses semantics, not string matching (the keyword-stuffed upper bound is
100\% for both). Column-role grounding from the request reaches \textbf{83\%} on
type-disambiguated roles (categorical group vs.\ numeric value) and 74\% overall;
the shortfall is genuinely symmetric roles (a weighted mean's value-vs-weight, a
pooled rate's numerator-vs-denominator) that the request does not uniquely fix
---an \emph{ambiguity}, not a method failure.

\subsection{End-to-end from only a request and a table}\label{sec:e2e}
Table~\ref{tab:e2e} runs the full pipeline with nothing template-given. On

column roles also inferred (only a messy sentence and a raw table), 51\%---3

not a headline}: roughly half of silent errors still pass, so the deployable
regime remains the structured-intent $98\%/0.2\%$; the value here is

\paragraph{Where the loss is.}
Pooling across five vendors ($N{=}115$) tightens the full-system estimate to
$\mathbf{57\%}$ [48--66] (width $18$ vs.\ $38$ at $N{=}23$) and lets us
\emph{decompose} the miss: of 49 misses, $\mathbf{53\%}$ are
contract-\emph{synthesis} failures, $\mathbf{31\%}$ operator-\emph{inference},
$16\%$ both---so invariant synthesis, not operator inference, is the dominant gap
(26 vs.\ 15; intervals overlap, directional) and the concrete future-work target.
De-leaked synthesis alone at $N{=}115$ holds at $80\%$ [72--86] CORE (GPT-5.5
$96\%$, codex $87\%$, GPT-5.4 $78\%$, Gemini $74\%$, Opus $65\%$), so the
feasibility number is not a single-model artifact.

\paragraph{Exemplar prompting does not fix synthesis (ablation).} Showing the
synthesizer a worked contract does \emph{not} help: over $k{=}3$ runs/vendor,
zero-shot is the most stable arm (pooled $72\%$; GPT $83{\pm}0\%$) while
one/few-shot fall to $57{\pm}9\%$/$54{\pm}7\%$---within run-to-run noise, so
zero-shot is the right default. Residual failures concentrate on
mechanically-intricate operators (index alignment, dtype coercion, resample
boundaries)---a fine-tuning/tool-use target, not a prompting fix.

\subsection{Substrate-agnostic transfer (pandas $\to$ SQL)}\label{sec:sql}
Because a contract reads only $(D,\theta,r)$, the \emph{same} contracts fire on
the identical semantic slip written in SQL. Over 10 operators (weighted AVG,
\texttt{WHERE g IS NOT NULL}, join fan-out, inner-join drop, \texttt{AVG} of
ratios, missing \texttt{DISTINCT}, \texttt{COUNT(col)} vs \texttt{COUNT(*)},
window \texttt{OVER()} vs \texttt{PARTITION BY}, \dots) the contracts fire on
every SQL slip and pass every correct SQL, with \textbf{zero} SQL-specific code
(10/10, CI 72--100). We do not over-claim: these invariants are
conservation/range/row-count properties that transfer by construction; operators
whose invariant relies on pandas-specific NaN semantics would need restating.

\section{Zero-Training Repair}\label{sec:repair}
% =============================================================================
Feeding the violated invariant back as a targeted repair prompt fixes silent
errors far better than strong goldless self-repair (Table~\ref{tab:repair}).
Targeted repair reaches \textbf{75\%} vs.\ \textbf{12\%} for a strong self-debug
baseline (per-value re-derivation $+$ decision enumeration $+$ self-critique),
with \emph{disjoint} intervals; localization-only reaches 52\%, so the invariant
\emph{content}---not merely knowing \emph{where} to look---adds a further $+23$
points. A telling negative result: strong self-debug (12\%) underperforms even generic
retry (18\%), because it confidently ``re-derives'' the same wrong operator; only
an \emph{external} specification breaks the loop. Best-of-$N$ selection using the
contract (no gold) adds further gains with zero mis-repairs.

\paragraph{The contract as a verifier: test time vs.\ training.} We probe the
contract as a reusable goldless \emph{verifier signal} on open models, where
retraining is feasible (Qwen-2.5-Coder; held-out silent starts, gold hidden).
Using the contract only to \emph{select} among $N$ goldless repair samples lifts
the fix rate from $28\%$ to $\mathbf{48\%}$ (best-of-6, contract-pass $0.72$, zero
over-repair), and the gain \emph{grows with scale} ($29\%$ at 3B ${\to}$ $48\%$ at
7B)---a goldless instance of test-time verification \citep{snell2024testtime}.
Yet using the \emph{same} contract to label preference pairs for offline DPO does
\emph{not} help---it moves the 7B by $-4$ to $-8$ points. The goldless verifier
therefore pays off at inference time (selection, repair feedback), not yet as a
training signal---a targeted, honest data point for the verifiable-reward
program (Sec.~\ref{sec:related}).

\section{Limitations and Honest Boundaries}\label{sec:limits}
% =============================================================================
\textbf{Conditional validity.} The method's strength lives where operator-level
intent is recoverable. On \emph{raw free-text code} (DS-1000), inferring which
operator to check is the bottleneck and no operating point reaches usable
recall/precision; a calibrated scope-gate instead makes out-of-scope inputs
\emph{abstain}, cutting spurious firing from 55\% to 5\%. The deployable claim is
``NL intent recoverable,'' not ``arbitrary code.''
\textbf{Taxonomy coverage.} Contracts detect the slips they specify; we report
coverage honestly and treat the self-authored grid as a unit test, not evidence
of generalization---the real-data 98\%/0.2\% shows detection generalizes across
real input \emph{tables} under a known operator (the pure-invariant contract is
the non-circular core), while cross-\emph{operator} generalization is
Sec.~\ref{sec:e2e}.
\textbf{Small samples.} Per-condition slices start small
($N{=}23$--$35$); we mitigate by pooling across vendors---synthesis and
end-to-end to $N{=}115$ (five vendors), repair to $N{=}65$ (four models)
(Sec.~\ref{sec:e2e}, interval width $38{\to}18$)---but still report every
CI rather than significance.
\textbf{Symmetric roles.} For operators with interchangeable
numeric roles the request may not fix which column is which; we score this as
ambiguity. \textbf{End-to-end ceiling.} The 51--58\% zero-structure figure is an
early-warning floor, well below the structured-intent regime, and its dominant
failure is invariant synthesis, not operator inference.
\textbf{Ecological validity of the prevalence measurement.} The 77\% headline is
the paper's primary contribution, so what it is conditioned on matters: the
Nature \emph{tables} are real, but the ambiguous \emph{requests} are author-written
templates designed to model how a hurried analyst under-specifies intent, not a
sampled corpus of deployed analyst prompts. The clarified-phrasing drop to 10\%
shows the ambiguity---not task difficulty---drives the errors, but it does not
establish how often real requests are this ambiguous; quantifying the ambiguity
distribution of deployed requests is the key threat to external validity. A pilot
on 40 real StackOverflow-derived requests (DS-1000, ambiguity-prone families, each
reduced to its prose intent) indicates operator ambiguity is common in the
wild---flagged for $22\%$ [12--38] by a conservative keyword detector and $80\%$
[65--90] by an LLM judge (single free model; per-item labels released)---so the
ambiguous regime is ecologically common rather than a contrived trap, though the
precise deployment distribution remains future work. \textbf{Gold-label reliability.} Gold is the author-written template
transform; we did not run a second-rater agreement study, so the $4/1855$
false-positives---attributed above to degenerate tables---are not independently
adjudicated.
\textbf{Reproducibility and precision.} Frontier generations use default API
sampling (reasoning models are not bit-reproducible even at temperature 0), so we
repeat the synthesis/ablation $k{=}3\times$ and report mean$\pm$sd: zero-shot
synthesis is stable (GPT $83{\pm}0\%$) while the exemplar effect is within
run-to-run noise (Sec.~\ref{sec:synth}). End-to-end and repair remain single
draws whose stochasticity exceeds the task-clustered Wilson intervals; fuller
averaging is future work.

% =============================================================================
\section{Conclusion}
% =============================================================================
LLMs silently compute the wrong data transform far more often than execution- or
shape-based checks reveal (77\% under ambiguous requests; 0\% caught by simple
safeguards). Specification-derived operator contracts detect these errors without
a per-task gold reference (98--99\%/0.2\%), can be synthesized from a high-level
request, transfer across execution substrates, and drive a zero-training repair
recipe---and the whole pipeline runs end-to-end from only a messy request and a
raw table. We frame silent-error detection as \emph{grounding an informal intent
into a verifiable specification}, and release the measurement suite and code.
