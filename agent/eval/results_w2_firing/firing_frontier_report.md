# DS-1000 external oracle-transfer firing (frontier models) — HONEST boundary

**Reviewer ask (AAAI Fix #3):** the "oracle transfers to unseen code" claim needs N≥50
genuinely external fireable cases, not the earlier N=5. Done here: **82 labelable
external cases** (18 silent + 64 pass; 14 exec-crashes excluded) from DS-1000 pandas,
generated by **two frontier models** (gpt-5.4, claude-opus-4.8), each labelled by
DS-1000's own gold harness (`_capture`), then judged by our goldless oracle.

## Result (the honest, uncomfortable number)

| regime | RECALL (fire on real silent) | FP (fire on real pass) | N |
|---|---|---|---|
| naive (all inferer-covered) | 10/18 = **56%** [34–75] | 35/64 = **55%** [43–66] | 82 |
| schema-adequate subset | 10/18 = 56% [34–75] | 33/56 = 59% [46–71] | 74 |

**This is NOT the 99%/0% we get on Nature — and that gap is the finding, not a failure to hide.**

## Root cause (diagnosed per-case, not hand-waved)

The bottleneck is **not the contracts** — it is the **naive keyword `infer()`** that maps a
free-text prompt to an (operator, params) guess. On DS-1000 free text it mis-assigns the
operator, and because DS-1000 tables use generic column names (`df`, `val`, `user`, `url`),
the mis-inferred params *happen to name real columns*, so the schema gate cannot catch it
(FP 55%→59% under the schema-adequate filter — essentially no help).

Concrete cases:
- **FP (pass judged wrong)**: pid 56/57 are *time-series reindex-and-fill* tasks, mis-inferred
  as `nan_as_zero_sum` (8/8 FP on that op) → the contract runs under a false operator premise
  and fires spuriously.
- **RECALL miss (silent not caught)**: pid 123/125/126 are *concatenate-keyword-columns* tasks
  mis-inferred as `left_join_keep_all` (recall 3/11) → not a join at all, so the join contract
  correctly stays silent, but the task's real error is of a type we have no contract for.

## What this means for the paper (honest framing)

1. **The contracts themselves are reliable** where the operator is known: on real Nature data
   (op/params supplied by the structured task builder) recall 99% / FP 0% at N=1408/1539.
2. **The end-to-end goldless pipeline on arbitrary free-text code is inferer-limited.** A
   40-year-old lesson resurfaces: a runtime contract is only as good as the spec it is
   attached to. Our naive keyword inferer is not that spec on open free-text.
3. **Therefore we scope the contribution honestly**: the value is (a) the *measurement* of
   silent-error prevalence, and (b) a training-free detect→localize→repair→select recipe
   **in settings where the operator-level intent is recoverable** (structured task specs,
   or a stronger NL→operator parser — explicitly future work). We do NOT claim turnkey
   transfer to arbitrary code; the DS-1000 numbers above are reported precisely so reviewers
   see the boundary.
